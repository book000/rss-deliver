# rss-deliver

A personal RSS collector and deliverer. It scrapes news sites, blogs, calendars and web comics that do not provide a usable feed, converts them to RSS 2.0, and publishes the result on GitHub Pages: <https://book000.github.io/rss-deliver/>.

This is a private-use project (`"private": true`). The sources and the published URL are hard-coded for the author's own use.

## How it works

`pnpm start` (`src/main.ts`) runs once per invocation:

1. Loads the deleted-articles history from `https://book000.github.io/rss-deliver/deleted-articles-history.json`.
2. Runs every service in parallel. For each service it loads the previously published feed from GitHub Pages, calls the service's `collect()`, fills in missing `pubDate` values, and writes `output/<ServiceClassName>.xml`. One failing service does not stop the others.
3. Compares the previous feed with the new items to detect articles that disappeared, and records them in `output/deleted-articles-history.json` (entries older than 30 days are dropped). The file is written on every run, because `output/` is deployed wholesale and a skipped write would drop it from the site.
4. Writes `output/index.html`, a list of the generated feeds built from `template.html`.

`pubDate` handling: an item without a `pubDate` inherits it from the previous feed, then from the deleted-articles history, and finally falls back to the current time.

## Requirements

- Node.js: the version in `.node-version`
- pnpm: the version in `packageManager` of `package.json` (npm and yarn are rejected by the `preinstall` script)
- Build tools and libraries for `canvas`: on Debian/Ubuntu, the packages in `.github/apt-packages.txt` (`build-essential`, `libcairo2-dev`, `libgif-dev`, `libjpeg-dev`, `libpango1.0-dev`, `librsvg2-dev`)

## Usage

```bash
pnpm install        # install dependencies
pnpm start          # collect all sources once and write ./output
pnpm dev            # same, restarting on file changes (tsx watch)
pnpm lint           # prettier --check, eslint and tsc
pnpm fix            # prettier --write and eslint --fix
```

`pnpm start` sends real requests to every source and to `book000.github.io`. It needs network access but no credentials.

There is no test framework. `src/verify/disney-parks-new-shows.ts` is an offline verification script for the `DisneyParksNewShows` classifier, parsers and merge logic; it uses the fixtures in `src/verify/fixtures` and makes no network requests:

```bash
pnpm exec tsx src/verify/disney-parks-new-shows.ts
```

## Configuration

There are no environment variables or configuration files. Sources, feed URLs and limits are constants in the source code. In GitHub Actions, the only secret is `DISCORD_WEBHOOK` (used for the failure notification described below).

## Output

Everything is written to `output/` (git-ignored):

- `<ServiceClassName>.xml`: one RSS 2.0 feed per service
- `index.html`: list of the feeds
- `deleted-articles-history.json`: articles that disappeared from a feed, kept for 30 days (written on every run; see "How it works")
- `popute/`, `fish4koma/`, `tdr-updates/`: images generated by the services, named by the MD5 hash of their content

Article pages fetched by some services are cached in `.article-cache/` (git-ignored). The cache lifetime is 7 days.

## Deployment

The `Update RSS` workflow (`.github/workflows/update-rss.yml`) runs hourly (`0 * * * *`), on push to `main`/`master`, and on manual dispatch. The `update-rss` job runs on a self-hosted runner and does the following:

1. Installs the apt packages and dependencies.
2. Restores the image cache (`output/popute`) and the article cache (`.article-cache`).
3. Runs `pnpm start`.
4. Saves both caches.
5. Sends a Discord notification (`DISCORD_WEBHOOK`) if a step fails.
6. Uploads `output/` as the GitHub Pages artifact.

A separate `deploy` job on `ubuntu-latest` then deploys the artifact to GitHub Pages. Because `output/` is uploaded as a whole, a service that produced no file in a run is absent from the deployed site until a later run succeeds.

The `Node CI` workflow (`.github/workflows/nodejs-ci-pnpm.yml`) runs the reusable pnpm CI from `book000/templates` on pushes and pull requests to `main`/`master`.

## Adding a service

1. Create `src/services/<name>.ts` with a class that extends `BaseService` and implements `information()` and `collect()`.
2. Register an instance in the `services` array in `src/main.ts`. The class name becomes the feed file name.

See `AGENTS.md` for development conventions.
